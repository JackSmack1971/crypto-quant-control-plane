CoinGecko, CoinPaprika, DexPaprika, Blockscout, and Alchemy returned **HTTP 403 Cloudflare error 1010** (`browser_signature_banned`). This repository does not set an `http_headers` User-Agent, because that workaround is unverified in Codex.

Configured endpoint URLs answered MCP `200` or an auth `401`. None of the eight HTTP URLs looked wrong on this probe.

## Decisions recorded in config

- **0xArchive allowlist** replaced the previous 10 names. Of those names, the hosted MCP doc page (retrieved with this change) states `get_candles` as an exact tool. It uses `get_symbol_coverage` and `get_data_incidents` as the coverage/incident examples, not `get_data_coverage`. The page also names `get_summary`, `get_funding_current`, `get_lighter_funding_current`, `get_hip3_summary`, and `get_hip4_outcomes`. Account and position tools named on that page are disabled in config, not allowlisted. Webhook and feedback tool identifiers were not in `tools/list` and are not invented here; the OAuth metadata is the evidence that those scopes exist. The allowlist is `DOCS_DERIVED_UNVERIFIED` until an authenticated `tools/list`.
- **CCXT** is pinned to `ccxt-mcp@0.1.3`. The committed config file sets `settings.hideDisabledTools` true and `settings.loadEnvKeys` false with an empty `accounts` object. Official docs and the current server source load that file from `CCXT_MCP_CONFIG`. The 0.1.3 process log already prints `hideDisabledTools`, defaulting false when no file is present. This change did not start the server again, so the hidden tool list is not a new observation. `enabled_tools` remains the client-side guard for the 10 market tools that the probe confirmed. `disabled_tools` denies the trading, funds, and account tools the probe listed. Market-tier tools outside the allowlist (`call_read_method`, `call_implicit_get`, and the `watch_*` tools) stay off the allowlist; `hideDisabledTools` is documented to hide disabled tiers, and those market/websocket tools are not those tiers.
- **CoinGecko** allowlist is the two probed tools. `execute` uses approval mode `approve`; other tools on that server use `prompt`.
- **CoinPaprika and DexPaprika** allowlists are the probed tools minus `submitFeedback`, which is also on `disabled_tools`.
- **Blockscout** allowlist is the probed tools minus `direct_api_call`, which is on `disabled_tools`.
- **OpenAI Docs** allowlist is the five probed tools.
- **Helius** package argument is `helius-mcp@2.3.0`, `enabled = false`, and `disabled_tools` lists `heliusWrite`, `heliusStreaming`, and `heliusAccount`. `heliusChain` stays unreachable while the server is disabled; it is not treated as a safe family because it exposes `simulateTransaction`.
- **Alchemy** stays disabled. **Massive** stays registered without a scope list: `tools/list` was not available, and the metadata `account` scope was not mapped to a research-only subset.
